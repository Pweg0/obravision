<objective>
Add automated weather alerts for climate-sensitive construction tasks via BullMQ cron job and Open-Meteo API.

Purpose: Brazilian construction sites are impacted by rain. Engineers need advance warning when weather threatens climate-sensitive tasks (concrete pouring, excavation, etc.) so they can reschedule or prepare.

Output: BullMQ repeatable job that checks weather daily, creates notifications for at-risk tasks, and integrates with the existing notification system from Phase 2.
</objective>

  <name>Task 1: Weather alert BullMQ queue, worker, and geocoding helper</name>
  <files>

  <behavior>
    - Worker fetches all active obras with lat/lon NOT null that have climate-sensitive tarefas in the next 3 days
    - Worker calls Open-Meteo once per obra (not per tarefa) with lat/lon
    - For tasks 3 days out with precipitation_probability_max >= 50: creates "weather_preliminary" notification
    - For tasks 1 day out with precipitation_probability_max >= 50: creates "weather_confirmed" notification
    - Worker skips obras where lat/lon is null
    - Worker skips API call if no climate-sensitive tasks exist in the date range
    - Notifications go to ADMIN + ENGENHEIRO members of the obra (not CLIENTE)
  </behavior>
  <action>
    1. Install date-fns in api: `pnpm --filter api add date-fns`
    2. Create `weather-alert.queue.ts`:
       - Import connection from pdf-conversion.queue.ts (reuse same Redis)
       - Export `WeatherAlertJobData` interface (empty — no per-job data needed, worker queries DB)
       - Export `weatherAlertQueue` with same retry config as pdf-conversion
       - Export `registerWeatherAlertScheduler()` that calls `upsertJobScheduler("daily-weather-check", { pattern: "0 7 * * *" }, ...)`
    3. Create `weather-alert.worker.ts`:
       - Extract the core detection logic into a testable pure function: `detectWeatherAlerts(tarefas, forecastData, targetDates)` that returns `{ tarefaId, alertType, precipitationProbability, alertDate }[]`
       - Worker process function:
         a. Query all obras with lat != null AND lon != null
         b. For each obra, query climate-sensitive tarefas (where climaSensivel is true OR null with etapa.climaSensivel true) with startDate in next 3 days
         c. Skip if no matching tarefas
         d. Fetch Open-Meteo with obra.lat/lon
         e. Run detectWeatherAlerts logic
         f. For each alert: create Notification records for ADMIN+ENGENHEIRO members via prisma.notification.createMany
         g. Emit socket event "weather-alert" to obra room (non-fatal — same pattern as Phase 2)
    4. Update `app.ts`:
       - Import and call `registerWeatherAlertScheduler()` at Fastify startup, alongside existing PDF worker registration
       - Start the weather worker (same pattern as pdfWorker start)
    5. Create test `apps/api/tests/workers/weather-alert.test.ts`:
       - Test `detectWeatherAlerts` pure function: given tarefas and forecast data, returns correct alert types
       - Test: skips tasks with precipitation_probability_max < 50
       - Test: 3 days out = "weather_preliminary", 1 day out = "weather_confirmed"
       - Mock fetch for Open-Meteo responses
  </action>
  <verify>
    <automated>pnpm --filter api test -- tests/workers/weather-alert.test.ts</automated>
  </verify>
  <done>

Dual alert levels: preliminary (3d) and confirmed (1d). Tests verify detection logic with mocked weather data. registerWeatherAlertScheduler called at Fastify startup.

  <action>
1. Install socket.io on API and client: `pnpm add --filter api socket.io` and `pnpm add --filter web socket.io-client`

2. Create `apps/api/src/plugins/socketio.ts` — custom Fastify plugin (NOT fastify-socket.io npm package per RESEARCH.md anti-pattern):
   - Export a Fastify plugin that, after `fastify.ready()`, creates `new SocketIOServer(fastify.server, { cors: { origin: process.env.WEB_URL ?? 'http://localhost:3000', credentials: true } })`.
   - Handle `connection` event: listen for `join-obra` (socket.join(`obra:${obraId}`)) and `leave-obra` (socket.leave(`obra:${obraId}`)).
   - Decorate fastify instance with `io` so routes can access it via `fastify.io`.
   - Export the Socket.io server instance for use by the BullMQ worker (tiles-ready event).

3. Update `apps/api/src/app.ts`:
   - Register the socketio plugin.
   - Ensure the Socket.io server is initialized before the Fastify server starts listening.
   - Add `NEXT_PUBLIC_API_URL` to env validation if not already present.

4. Create `apps/api/src/routes/notifications.ts` — Fastify routes:
   - POST `/api/notifications/emit` — accepts `{ event: string, obraId: string, data: object }` and emits the event to `obra:${obraId}` room via `fastify.io`. This is called by Next.js server actions after creating pins/replies/revisions. Events: "new-pin", "new-reply", "new-revision", "mention".
   - POST `/api/notifications/create` — accepts `{ userId, tenantId, type, payload }`, creates Notification record in DB, and emits socket event to the user's obra room. This centralizes notification creation so both server actions and BullMQ workers can use it.

5. Create `apps/web/providers/SocketProvider.tsx` following RESEARCH.md Pattern 3 exactly:
   - "use client" component with Context + useEffect.
   - Connects to `process.env.NEXT_PUBLIC_API_URL` with `withCredentials: true`.
   - Joins `obra:${obraId}` room on mount, leaves on unmount.
   - Exports `useSocket()` hook.
   - Initialize socket ONLY in useEffect (RESEARCH.md Pitfall 3 — avoid SSR crash).

6. Create `apps/web/lib/actions/notification.ts` — Server Actions:
   - `listNotifications(options?: { limit?: number; unreadOnly?: boolean })` — returns notifications for current user, ordered by createdAt desc. Default limit 20.
   - `markAsRead(notificationId: string)` — sets readAt to now().
   - `markAllAsRead()` — sets readAt on all unread notifications for current user.
   - `getUnreadCount()` — returns count of notifications where readAt is null for current user.
   - `emitNotification(obraId: string, event: string, data: object, recipientUserIds: string[], type: string, payload: object)` — helper that: (a) creates Notification records for each recipient, (b) calls Fastify API POST /api/notifications/emit to broadcast socket event. Used by pin.ts and thread.ts actions.

7. Update the pin creation and thread reply actions (from Plan 02) to call `emitNotification` after successful creation:
   - createPin: emit "new-pin" to obra room, create notifications for all obra members except author
   - addMessage: emit "new-reply" to obra room, create notifications for thread participants + @mentioned users
   - createRevisao (from Plan 01): emit "new-revision" to obra room, create notifications for all obra members except uploader
   NOTE: If Plan 02 hasn't been executed yet, add a note in the code with `// TODO: Wire emitNotification after Plan 02 creates these actions`. If the actions exist, wire them directly.

8. Create `apps/api/tests/socket/obra-room.test.ts`:
   - Test that a client can connect, join an obra room, and receive events emitted to that room.
   - Test that events emitted to obra:A are NOT received by clients in obra:B.
   - Use socket.io-client to create test clients connecting to an in-memory Fastify server.

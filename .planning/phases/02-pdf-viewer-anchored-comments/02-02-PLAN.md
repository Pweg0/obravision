1. Install react-pdf: `pnpm add --filter web react-pdf pdfjs-dist`

2. Create `apps/web/lib/validations/pin.ts` with Zod schemas:
   - `createPinSchema`: x (number 0-1), y (number 0-1), pageNumber (positive int), content (1-2000 chars, initial comment text)
   - `addMessageSchema`: content (1-2000 chars), mentions (optional string array of user IDs)

3. Create `apps/web/lib/actions/pin.ts` — Server Actions:
   - `createPin(plantaRevisaoId: string, formData: FormData)` — validates with Zod, creates Pin + Thread + initial ThreadMessage atomically in a transaction. Permission: Admin + Engenheiro only (check session.user.role). Returns the created pin with thread. Calls revalidatePath.
   - `deletePin(pinId: string)` — soft delete (set deletedAt on Pin, Thread, and all ThreadMessages). Permission: pin author or Admin.
   - `listPinsByRevisao(plantaRevisaoId: string)` — returns all pins (not soft-deleted) with their author info (name, image for avatar) for the given revision and page. Include thread message count.

4. Create `apps/web/lib/actions/thread.ts` — Server Actions:
   - `addMessage(threadId: string, formData: FormData)` — validates content + mentions with Zod. Creates ThreadMessage. Permission: Admin + Engenheiro. Parse @mentions from content to populate mentions array. Calls revalidatePath.
   - `deleteMessage(messageId: string)` — soft delete. Permission: message author or Admin.
   - `getThread(pinId: string)` — returns thread with all messages (including soft-deleted ones showing "Mensagem removida"), author info (name, image), and creation dates.

5. Create `page.tsx` (Server Component) at `/dashboard/obras/[id]/plantas/[plantaId]`:
   - Fetch planta with all its revisoes (not soft-deleted), ordered by createdAt desc
   - Fetch the latest revisao's pins with author info
   - Determine user role from session for permission checks
   - Render PlantaViewerClient with planta, revisoes, pins, currentRevisao, and userRole props

6. Create `PlantaViewerClient.tsx` (Client Component) — the main viewer:
   - State: currentRevisaoId, pageNumber, numPages, scale (default 1.0), selectedPinId, tempPin (for creation flow)
   - Layout: horizontal toolbar at top, viewer area taking remaining height. Viewer embedded in obra page (NOT full-screen per locked decision). When a pin is selected, viewer shrinks and ThreadSidebar appears on the right.
   - Rendering logic: if `currentRevisao.tilesReady` is true, render `TileViewer`; otherwise render react-pdf `<Document>` + `<Page>`.
   - For react-pdf: configure worker via `pdfjs.GlobalWorkerOptions.workerSrc` using `import.meta.url` pattern from RESEARCH.md Pitfall 2. Disable renderTextLayer and renderAnnotationLayer. Use the R2 public URL + r2Key as the file source.
   - Pin creation flow (locked decision): click on viewer area calls clickToNormalized to get normalized coords, sets tempPin state, shows PinPopup. Cancel clears tempPin. Submit calls createPin server action.
   - Pin selection: clicking an existing pin sets selectedPinId and opens ThreadSidebar.

7. Create `ViewerToolbar.tsx`:
   - Zoom controls: "-" button, zoom percentage display, "+" button. Zoom steps: 0.5, 0.75, 1.0, 1.25, 1.5, 2.0.
   - Page navigation: "<" prev, "Page {N} of {total}" display, ">" next.
   - RevisionDropdown on the right side.
   - Plant name on the left side.

8. Create `RevisionDropdown.tsx`:
   - Dropdown showing all revisions: "R2 (atual)" for latest, "R1", "R0" for older.
   - Selecting a revision updates currentRevisaoId in parent, which reloads pins for that revision.
   - "Enviar nova revisao" button at bottom of dropdown that opens PlantaUploadForm (from Plan 01) in revision mode.

9. Create `TileViewer.tsx`:
   - Renders WebP tiles from R2 for large PDFs where tilesReady=true.
   - Shows tile image for current page: `{R2_PUBLIC_URL}/{tilesPrefix}/page-{pageNumber}.webp`
   - Image scales with the zoom factor via CSS transform or width.
   - Wrapping div has same relative positioning as react-pdf canvas for PinLayer overlay compatibility.

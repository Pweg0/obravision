Create validations/estoque.ts with Zod schemas: createDepositoSchema (obraId, nome), addMovimentacaoSchema (depositoId, tipo, descricao, unidade, quantidade, quantidadeMinima optional, depositoDestinoId optional for TRANSFERENCIA, pedidoId optional, tarefaId optional, etapaId optional, observacoes optional).

    2. Create actions/estoque.ts server actions:
       - createDeposito(obraId, nome): creates Deposito
       - listDepositos(obraId): returns all depositos for the obra
       - addMovimentacao(data): creates MovimentacaoEstoque. For tipo=SAIDA, wrap in $transaction: query current saldo first, verify saldo >= quantidade, then insert. For tipo=TRANSFERENCIA, create SAIDA on source + ENTRADA on destination in same $transaction. After SAIDA, call checkLowStock.
       - getEstoqueAtual(depositoId): aggregates MovimentacaoEstoque by descricao, sums ENTRADA quantities positive and SAIDA negative, returns net balance per material with quantidadeMinima from latest entry.
       - getEstoqueResumo(obraId): across all depositos, returns material balances with low stock flag.
       - deliverPedido(pedidoId): in a prisma.$transaction: (1) update CompraPedido status to ENTREGUE + set entregueEm, (2) update CompraRequisicao status to ENTREGUE, (3) create MovimentacaoEstoque with tipo=ENTRADA, descricao from requisicao, quantity from pedido, pedidoId link. Must select the first deposito of the obra (or a default). Returns error if already ENTREGUE.
       - checkLowStock(depositoId, descricao): calculates current saldo, finds quantidadeMinima from the most recent ENTRADA for that material, if saldo < minima emits notification "estoque-baixo" to obra ADMIN and ENGENHEIRO users via emitNotification.

    Permissions: Admin + Engenheiro can manage estoque. Cliente role is view-only (checked in server actions via requireAdminOrEngenheiro).

    Anti-patterns to avoid:

    - Do NOT create ENTRADA and SAIDA separately for TRANSFERENCIA — must be atomic $transaction

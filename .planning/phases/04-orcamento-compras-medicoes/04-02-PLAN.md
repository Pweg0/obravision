    - buildCurvaABC([]) returns empty array
    - buildCurvaABC with single item returns [{percentual_acumulado: 100, categoria: "C"}]
    - A threshold: <= 50%, B threshold: <= 80%, C threshold: > 80%
  </behavior>
  <action>
    1. Install @react-pdf/renderer in API package: `pnpm --filter api add @react-pdf/renderer`

    2. Create a pure function `buildCurvaABC` in apps/web/lib/orcamento-utils.ts:
       - Input: array of {id, descricao, unidade, quantidade, custoUnitario}
       - Calculate valorTotal = quantidade * custoUnitario per item
       - Sort by valorTotal DESC
       - Calculate running sum / grand total * 100 as percentual_acumulado
       - Classify: A if percentual_acumulado <= 50, B if <= 80, C if > 80
       - Return enriched array

    3. Add tests to tests/lib/orcamento.test.ts for buildCurvaABC (ORC-05).

    4. Create pdf-generation.queue.ts: define queue name "pdf-generation", job data type PdfGenerationJobData { type: "proposta" | "pedido-compra" | "boletim-medicao", entityId: string, obraId: string, tenantId: string }. Export addPdfJob helper.

    5. Create pdf-generation.worker.ts following existing pdf-conversion.worker.ts pattern:
       - Import renderToBuffer from @react-pdf/renderer
       - Switch on job.data.type to select template
       - Fetch data from DB, render template, upload to R2, update entity pdfR2Key
       - Emit "pdf-ready" socket event to obra room
       - Concurrency: 3

    6. Create PropostaComercial.tsx as a @react-pdf/renderer template:
       - Header: empresa name, obra name, date
       - BDI percentage display
       - Table of etapas and items with Custo Unitario, Quantidade, Custo Total
       - Grand total with BDI applied (Preco Venda)
       - Footer with page numbers

    7. Create orcamento-pdf.ts server action:
       - enqueueProposta(orcamentoId): validates permissions, enqueues "proposta" job to BullMQ, returns { status: "queued" }
       - getPropostaPdfUrl(orcamentoId): checks Orcamento.pdfR2Key, generates presigned GET URL, returns download URL

    Anti-patterns to avoid:
    - Do NOT render PDF synchronously in server action — always enqueue to BullMQ
    - Do NOT use JS number for Decimal values in PDF template — convert Decimal.toFixed(2) for display
  </action>

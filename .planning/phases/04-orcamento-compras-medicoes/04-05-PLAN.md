  <action>
    1. Create medicoes-utils.ts with calcularProgressoPonderado pure function:
       - Input: array of { valorTotal: Decimal, percentualExecutado: number }
       - Formula: SUM(valorTotal * percentualExecutado/100) / SUM(valorTotal) * 100
       - Returns number with 1 decimal place
       - Handle edge case: empty array returns 0, zero total returns 0
       - Use Decimal.js for all arithmetic (never JS number for financial calc)

    2. Create validations/medicoes.ts with Zod schemas: createMedicaoFisicaSchema (obraId, orcamentoId, periodo), updateMedicaoFisicaItemSchema (medicaoId, orcamentoItemId, percentualExecutado 0-100), createMedicaoContratoSchema (obraId, empreiteiroNome, empreiteiroCnpj, periodo), addContratoItemSchema (medicaoId, descricao, unidade, quantidadeContratada, quantidadeExecutada, valorUnitario).

    3. Create actions/medicoes.ts server actions:
       - createMedicaoFisica(obraId, orcamentoId, periodo): creates MedicaoFisica with PENDENTE status. Auto-generates MedicaoFisicaItem rows for ALL OrcamentoItem in the orcamento (percentualExecutado = 0).
       - updateMedicaoFisicaItem(medicaoFisicaItemId, percentualExecutado): updates percentage (0-100). Recalculates MedicaoFisica.progressoGeral via calcularProgressoPonderado.
       - getMedicaoFisica(medicaoId): returns medicao with all items including orcamentoItem details (descricao, quantidade, custoUnitario).
       - listMedicoesFisicas(obraId): returns all physical measurements ordered by periodo DESC.
       - createMedicaoContrato(data): creates MedicaoContrato with PENDENTE status.
       - addContratoItem(data): creates MedicaoContratoItem. Validates quantidadeExecutada <= quantidadeContratada.
       - getMedicaoContrato(medicaoId): returns contrato with items and cumulative totals from prior periods (same empreiteiro).
       - listMedicoesContrato(obraId): returns all contract measurements ordered by periodo DESC.
       - approveMedicao(type: "fisica" | "contrato", medicaoId): ADMIN only (not ENGENHEIRO per locked decision — Admin aprova medicoes). Updates status to APROVADA, sets aprovadoPor/aprovadoEm. Emits notification to the measurement creator.
       - rejectMedicao(type, medicaoId, motivo): ADMIN only. Updates status to REJEITADA.
       - exportBoletim(type, medicaoId): enqueues "boletim-medicao" PDF job to BullMQ. Returns { status: "queued" }.
       - getBoletimPdfUrl(type, medicaoId): generates presigned GET URL for pdfR2Key.

    4. Create BoletimMedicao.tsx react-pdf template:
       - Header: empresa name, obra name, periodo, type (Fisica/Contrato)
       - For Fisica: table of items with descricao, quantidade orcada, percentual executado, valor executado. Footer: progresso geral ponderado.
       - For Contrato: empreiteiro info (nome, CNPJ). Table of items: descricao, qtd contratada, qtd executada, valor unitario, valor executado. Acumulado section showing prior period totals.
       - Approval status and signature line
       - Footer with page numbers

    5. Update pdf-generation.worker.ts to handle type "boletim-medicao" — import BoletimMedicao template, fetch MedicaoFisica or MedicaoContrato data based on subtype. Note: Plan 04-03 already extended this worker with "pedido-compra" support; add the "boletim-medicao" case alongside it in the switch statement.

    6. Create test files:

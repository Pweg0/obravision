    - Password reset: Forgot-password creates PasswordResetToken with 1h expiry. Reset-password with valid token updates passwordHash and marks token used. Expired/used token returns error.

  <action>
    1. Create `apps/web/lib/validations/auth.ts`:
       - Zod schemas: `loginSchema` (email, password min 8), `registerSchema` (name, email, password min 8, confirmPassword), `forgotPasswordSchema` (email), `resetPasswordSchema` (token, password min 8, confirmPassword)

    2. Create `apps/web/lib/auth.ts` — Auth.js v5 configuration:
       - Import `NextAuth` from `next-auth`, `PrismaAdapter` from `@auth/prisma-adapter`, `Credentials` and `Google` providers
       - `session: { strategy: "jwt" }` (REQUIRED — credentials provider breaks with database sessions)
       - Credentials provider: authorize function validates email/password with bcrypt.compare against user.passwordHash
       - Google provider with env vars
       - JWT callback: store `id`, `empresaId`, `role`, `onboardingStep` in token
       - Session callback: expose `id`, `empresaId`, `role`, `onboardingStep` on session.user
       - Export `{ handlers, auth, signIn, signOut }`

    3. Create `apps/web/app/api/auth/[...nextauth]/route.ts`:
       - Export `{ GET, POST }` from `handlers` in auth.ts

    4. Create `apps/web/lib/auth-actions.ts` — Server Actions:
       - `register(formData)`: Validate with registerSchema, check email uniqueness, hash password with bcrypt (salt rounds 12), create User via Prisma, call `signIn("credentials")`, return success
       - `login(formData)`: Validate with loginSchema, call `signIn("credentials")` with redirect: false, return result
       - `forgotPassword(formData)`: Validate email, find user, create PasswordResetToken with nanoid(32) and 1h expiry, send email via Resend with reset link (`/reset-password?token=...`), return success even if email not found (prevent enumeration)
       - `resetPassword(formData)`: Validate with resetPasswordSchema, find token (not expired, not used), hash new password, update user.passwordHash, mark token usedAt, return success

    5. Create `apps/web/middleware.ts`:
       - Protect `/dashboard/*` and `/onboarding/*` — redirect to `/login` if no session
       - If session exists but `empresaId` is null and path starts with `/dashboard` — redirect to `/onboarding/empresa`
       - Allow `/`, `/login`, `/register`, `/forgot-password`, `/reset-password`, `/api/auth/*` without auth
       - Use `auth` from auth.ts as the middleware wrapper (Auth.js v5 pattern: `export default auth(...)`)

    6. Create auth UI pages using shadcn/ui components (Card, Input, Button, Label, Form):
       - `(auth)/layout.tsx`: Centered layout with ObraVision logo, no sidebar
       - `(auth)/login/page.tsx`: Email + password form, "Esqueceu a senha?" link, Google OAuth button (calls signIn("google")), "Criar conta" link
       - `(auth)/register/page.tsx`: Name + email + password + confirm password form, Google OAuth button, "Ja tem conta?" link
       - `(auth)/forgot-password/page.tsx`: Email form, "Voltar ao login" link, success message after submit
       - `(auth)/reset-password/page.tsx`: Reads `?token=` from URL, new password + confirm password form, validates token server-side on submit
       - All forms use React Hook Form + Zod resolver, show field-level validation errors
       - Use Verde Obra #1A6B5A as primary color, Inter font

    7. Create RLS isolation integration test `packages/db/tests/rls-isolation.test.ts`:
       - Use Vitest
       - Create two empresas with distinct tenantIds
       - Using `createTenantClient(tenantA)`, create an obra for tenant A
       - Using `createTenantClient(tenantB)`, query obras — assert count is 0
       - Using `createTenantClient(tenantB)`, attempt to INSERT obra with tenantA's tenantId — assert it fails (RLS WITH CHECK violation)
       - Clean up test data after each test

    ANTI-PATTERNS TO AVOID (from RESEARCH.md):
    - Do NOT use `session: { strategy: "database" }` — breaks credentials provider (AUTH-03)
    - Do NOT store passwordHash via the Prisma adapter — do it manually in register Server Action
    - Invite tokens must use nanoid, not sequential IDs
    - Session JWT MUST include empresaId and role (avoid extra DB query on every page)
    - Do NOT call auth() on the landing page layout
